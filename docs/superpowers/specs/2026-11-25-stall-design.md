# 좌판 (같은 상품의 개체 여러 점) 설계

## 왜
같은 상품이라도 제작 공정 때문에 한 점씩 디테일이 다르다. 전부 따로 찍지만 메인 타일에 다 올리면 도배가 된다.
생선직판장처럼, 한 자리에 깔아 두고 손님이 실물을 보고 고르게 한다.

## 정한 것 (사용자)
- 시안 A(펼침면)·B(번호판)·C(그리드) 중 **C**. 팝업 안이 아니라 그리드 화면 자체가 그 상품들로 바뀐다.
- 기존 무드 그대로: 흰 배경, 누끼, Helvetica, 검정·빨강. 레퍼런스는 `레퍼런스이미지/`.
- 번호는 `001` 형식.
- 적으면 비어 보이지 않게, 많으면 빽빽한 만족감이 나게.

## 접근
- A 펼침면: 설명을 나란히 봄. 대신 사진 칸이 화면 절반.
- B 번호판: 물량감. 대신 검은 테두리 팝업이라 그리드와 끊김.
- **C 그리드 (선택)**: 메인 그리드의 연장. 시안에서는 칸 크기가 고정이라 적을 때 비었음 → 칸 크기를 개수에 맞춘다.

## 배치 규칙
- 개수·화면 크기로 열 수를 정한다. 제목이 맨 앞 칸에서 시작해 남는 칸을 전부 차지하므로 **구멍 없는 직사각형**이 된다.
- 모두 한 화면에 들어오는 가장 큰 칸을 고른다. 칸 높이는 폭의 0.64~1.5배(최소 44px) 안에서 화면 높이에 맞춘다. 가로로 긴 사진이면 그 비율만큼 낮춘다.
- 칸은 최소 80px(모바일 6열)까지만 작아지고, 그보다 많으면 세로로 스크롤한다.
- 팔린 것은 자리를 남기고 흐리게, 번호는 빨강.

## 데이터
- `catalog_items`에 `parent_id`(대표 상품), `no`(번호)를 추가하고 `kind`에 `piece`를 추가한다.
- 대표 상품은 지금처럼 `kind = 'product'`. 낱개(`piece`)는 메인 그리드에 놓이지 않는다.
- 낱개의 이름·가격·크기·소재·설명·구매 링크가 비어 있으면 대표 상품의 값을 쓴다. 사진 확대·위치도 대표 상품의 값을 쓴다(같은 틀로 찍는다고 본다). 타일에서 보이는 범위가 좌판의 칸에 꽉 차게 환산한다.
- 번호는 대표 상품 안에서 1부터 늘고, 지워도 다시 매기지 않는다.
- 대표 상품을 지우면 낱개도 지워진다(판매 기록은 남음).
- 브랜드 로그의 포트폴리오 개수는 대표 상품 1개로 센다(`piece`는 `catalog_events`에 남지 않음). 판매 기록은 낱개에 연결할 수 있다.

## 방문자
- 메인 타일: 대표 사진. 마우스를 올리면(터치 기기는 저절로) 낱개 사진이 차례로 바뀌고 가격표는 `₩ 30,000 × 10`.
- 누르면 좌판, 낱개를 누르면 기존 상세 팝업(이름 뒤에 번호). 닫으면 좌판으로 돌아온다. Esc도 같은 순서.
- 주소의 `#id`로 좌판이나 낱개를 바로 열 수 있다.

## 관리자
- 상품 패널에 '좌판' 구역. 사진을 여러 장 놓으면 파일 이름 순으로 낱개가 생긴다.
- 낱개를 누르면 같은 패널에서 가격·설명·판매 완료·상세 사진을 고친다. 빈 값은 대표 상품의 값이 흐리게 보인다.

## 하지 않는 것
- 이미 있는 상품 여러 개를 하나의 좌판으로 묶기, 낱개 순서 바꾸기, 낱개 숨기기, 낱개별 사진 확대.

## 배포 순서
새 코드는 DB를 바꾸기 전에도 지금과 똑같이 동작한다. 코드 배포 → DB 변경 → 낱개 등록 순서로 한다(옛 코드는 낱개를 메인 타일로 그리므로).
